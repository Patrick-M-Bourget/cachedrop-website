# CacheDrop website: decisions

Grilled with the owner on 2026-10-29 from the design handoff in `handoff/`. These decisions override `handoff/HANDOFF.md` where they differ. Amend a decision by adding a new numbered one that names what it changes; never rewrite an old one.

The legal points below come from primary sources and law-firm summaries researched on 2026-10-29. They are not legal advice; a lawyer reviews the privacy policy before launch (Decision 15).

## Product

1. **The download is gated by a verified email.** `/download/` asks for an email and an optional "What's filling your Mac?" choice (Development, Video & photo, Music & audio, Other). Submitting sends an email with a download link; the page says to check the inbox. Only a real inbox gets the app. Every Download button on the site points at `/download/`.
2. **Download links.** The link opens `/download/<token>`, which shows the "Your download has started" content from the handoff and starts the download with a fresh 60-second signed URL from a private Supabase bucket. A token works for 7 days and can be reused on any Mac. The same email submitted again re-sends a link instead of adding a row. An expired token shows "This link has expired" with the email form. Tokens are deleted 30 days after they expire.
3. **Who gets which email.** Everyone who signs up gets the download email, "a new version is available" emails and security notices. None of these promote anything. Only people who tick an **unticked** box ("Email me news about CacheDrop, like new features, surveys and the paid launch") get anything else. The download never depends on that box. A pre-ticked box is not consent under CASL, Law 25 or GDPR.
4. **Unsubscribe.** Every email has one link that turns off both update emails and the opt-in, plus one-click unsubscribe headers (`List-Unsubscribe`, `List-Unsubscribe-Post`). No preferences page.
5. **Bilingual.** English at `/`, French at `/fr/`, with `hreflang` alternates. Emails go out in the language the person signed up in. The Charter of the French Language (s. 52) requires a Quebec business's commercial website to be available in French. Claude drafts the French; the owner reviews it.

## Feedback loop

6. **Feedback becomes a GitHub issue.** The feedback modal posts to a Vercel function. The function saves the row in Supabase, then creates an issue in `Patrick-M-Bourget/mac-cleaner` labelled `feedback` and `needs-triage`, with the rating, message, page and specs, **never the email**, and writes the issue number back to the row. A scheduled job retries rows with no issue. Website-only feedback moves to this repo by hand at triage.
7. **Human in the loop.** A daily Claude scheduled routine reads untriaged `feedback` issues and posts a proposed triage on each (bug or idea, likely duplicates, a proposed label, questions to grill). It never applies a `ready-*` label; the owner does, then grills. Its instructions live in mac-cleaner `docs/agents/feedback-triage.md`.
8. **GitHub access.** A fine-grained personal access token limited to mac-cleaner, Issues read and write only, stored as a Vercel production secret. The owner creates it. Move to a GitHub App if more repos need it.
9. **Replying to reporters** is out of scope for now. Emails stay in Supabase for manual lookup.
10. **The specs checkbox starts unchecked.** The handoff pre-checks it. Law 25 (art. 8.1) wants features that can identify a device off by default.

## Stack and infrastructure

11. **Astro, static output.** Port the handoff pages into Astro layouts and components. The rendered pages match the handoff except for the changes these decisions make, checked with screenshot comparisons at 1440 and 390 px against `handoff/screenshots/` and a diff of the head tags. Literal values become `var(--token)` from `handoff/design-system/tokens.css` in the same port. No React runtime on the pages.
12. **Server side.** Vercel functions hold the Supabase service key; browsers never write to Supabase directly. Cloudflare Turnstile plus a per-IP rate limit protect the email gate and the feedback form.
13. **Supabase.** Two projects, `prod` and `dev`, both in `ca-central-1` (AWS Montreal), so stored emails stay in Quebec. Free while building; `prod` moves to Pro the week of launch (Free projects pause after a week idle). The 4.9 MB DMG fits Free's 50 MB file cap.
14. **Email.** Resend, called from the Vercel function (not Supabase Auth, whose built-in email only reaches the project team). Sends from `cachedrop.io` with SPF and DKIM. Free plan (100 a day) to start; Pro if launch nears that.
15. **Releases** (amended by Decisions 36 and 37). A `releases` table and a private bucket. `scripts/publish-dmg.sh` in this repo uploads `CacheDrop-x.y.z.dmg` and marks it latest; the owner runs it after mac-cleaner's `release.sh`. The download page reads the version and filename from the table. Wiring it into `release.sh` waits for Sparkle (mac-cleaner #340), whose update feed is public and skips the gate.
16. **Analytics.** Vercel Web Analytics (cookieless), listed in the privacy policy, with no consent banner. `beforeSend` strips the token from `/download/<token>` URLs. Downloads are counted in our own table, not in analytics.
17. **Vercel.** Hobby while building; Pro before launch (Hobby is non-commercial only).
18. **Domain.** `cachedrop.io` (Namecheap, registered 2026-10-29) moves to Vercel's nameservers; `www` redirects to the apex. Every canonical, Open Graph URL, JSON-LD URL, sitemap and robots entry changes from `cachedrop.app` to `cachedrop.io`. DNS goes up now: Resend's records, and Namecheap mail forwarding (MX) for `privacy@` and `hello@cachedrop.io` to the owner's inbox. The site is attached to the domain only at launch.

## Compliance

19. **Privacy policy** in English and French, linked from the footer and from every form. It names the owner as the person in charge of the protection of personal information (Law 25 art. 3.1) with `privacy@cachedrop.io`; lists what is collected and why, the providers (Supabase, Vercel, Resend, Cloudflare, GitHub) and that some are outside Quebec; and states retention: signups until unsubscribe or a deletion request, tokens 30 days after expiry, specs with their feedback.
20. **Privacy impact assessment.** A short one in `docs/privacy/` covering the providers outside Quebec (Law 25 art. 17), written before launch.
21. **Mailing address.** A PO box or virtual mailbox is in place before launch, for CASL's sender identification and the privacy policy. The owner's home address is never published.
22. **A lawyer reviews** the privacy policy for about an hour before launch.

## Content

23. **Claims match the app.** "Cleaned items go to the Trash" is false for regenerable items, which mac-cleaner deletes permanently (RESET.md Decision 3). Rewrite to the mechanism, e.g. "Caches and build files that tools rebuild are deleted. Your files go to the Trash, so changing your mind is one drag away." Check every engineering claim in the handoff (HANDOFF.md §6.2, the Premiere menu path) against mac-cleaner `main`.
24. **The homepage app window** becomes a real screenshot of the shipping app's Overview, light and dark, taken from the release build at launch.

## Process

26. **Launch blocks on:** mac-cleaner #118 and #317 closed with the notarized DMG published through the script; the homepage screenshot re-shot from it; the French copy reviewed by the owner; the lawyer's review; the PO box; Supabase prod and Vercel on Pro; the impact assessment; and a test signup and feedback submission on production.

## Amendments

29. **DNS and mail on Cloudflare** (amends 18, 2026-10-29). Namecheap's free forwarding works only on Namecheap's own DNS, and there it can't coexist with Resend's `send` MX record (Mail Settings is either Email Forwarding or Custom MX). So `cachedrop.io` moves to Cloudflare's nameservers (Free plan), not Vercel's. Cloudflare Email Routing forwards `privacy@` and `hello@` to the owner's inbox; Resend's records and DMARC live in Cloudflare DNS. At launch the site is attached with DNS-only (unproxied) records pointing the apex and `www` at Vercel. Cloudflare is already a provider for Turnstile; the privacy policy and impact assessment add mail forwarding to its purposes.

30. **mac-cleaner goes private before launch** (amends 6 and 26, 2026-10-29). `Patrick-M-Bourget/mac-cleaner` is public today, so feedback issues created there would publish what people type and their specs. The repo is made private before launch, and launch blocks on it. The privacy policy describes the launch state: feedback goes to a private GitHub repository. Until then, only test feedback from previews reaches it.

31. **Supabase outside Quebec** (amends 13, 2026-10-29). The projects were created outside Quebec: `cachedrop-dev` in `us-east-1` (AWS N. Virginia) and `cachedrop-prod` in `us-west-2` (AWS Oregon). The owner chose to keep them there. Signups, feedback and releases are therefore stored in the United States. Law 25 allows this with the art. 17 impact assessment (Decision 20), which now covers Supabase. The privacy policy lists Supabase as a provider outside Quebec.

32. **Unsubscribe keeps a do-not-email marker** (amends 19, 2026-10-29). Signups are kept until a deletion request, not until unsubscribe. Deleting the signup at unsubscribe would break a live download link (Decision 2), and the next download request would forget the unsubscribe. After an unsubscribe, the signup keeps only the email address, marked so it is never emailed again; the other answers are cleared. Writing to `privacy@cachedrop.io` deletes it completely. The privacy policy says so. Ticking the news box again on a later download request is fresh consent: it clears the unsubscribe, and update and news emails resume. A request without the tick keeps the person unsubscribed.

33. **No mailing address for the beta** (amends 21 and 26, 2026-10-29). A PO box or virtual mailbox costs more than the beta justifies, so the policy and the emails carry no postal address, and launch no longer blocks on one. The owner's home address is still never published. The contact is `privacy@` and `hello@cachedrop.io`. CASL's sender identification asks for a mailing address in commercial messages, so revisit this before the first news email to people who ticked the opt-in.

34. **French copy ships as Claude drafted it** (amends 5 and 26, 2026-10-29). The owner chose not to review the French pages and emails before launch, so launch no longer blocks on that review. Emails go out in the language of the person's latest download request, and unsubscribing resets the stored language to English along with the rest of the do-not-email marker (Decision 32).

35. **Launch without the lawyer review or Pro plans** (amends 13, 17, 22, 26, 2026-10-29). The owner decided the privacy policy and the impact assessment need no lawyer's review before launch, and accepted the drafts as written. Supabase `prod` stays on Free and Vercel on Hobby; neither moves to Pro for launch. That keeps the limits Decisions 13 and 17 named: a Free project pauses after a week without activity, and Hobby is for non-commercial use. Launch no longer blocks on the lawyer's review or the Pro plans. The platform claim now follows the shipping build (Decision 23): mac-cleaner's Release configuration is `ARCHS = arm64` with `MACOSX_DEPLOYMENT_TARGET = 26.0` (checked at `b70960d`), so the site says Apple Silicon Macs with macOS 26 or later and no longer mentions Intel. When mac-cleaner #322 (lower the minimum) or #323 (Intel) lands, the claim changes with it.

36. **Stage identical updater and website artifacts separately** (amended by Decision 37 for promotion; amends 15, mac-cleaner #517, 2026-10-30). `scripts/stage-release.sh <dev|prod> DMG release-identity.json` stages an existing final signed stable-version DMG without rebuilding, signing, changing latest or publishing a feed. The artifact's filename, size, hash, approved public key and EdDSA signature are checked before uploading. A separate public `updates` bucket serves immutable `<version>/CacheDrop-x.y.z.dmg` objects; the existing `releases` bucket and emailed/tokenized website gate remain private. Both destinations must contain identical bytes, verified through actual public retrieval and the private signed-URL interface. Existing matching objects are reused; conflicts are refused without replacing bytes; an identical retry resumes a partial upload. Both buckets retain the 50 MB cap. Targets are allowlisted to the existing dev and prod projects: dev reads only `.env.local`, prod reads shell credentials and requires explicit confirmation. Acceptance uses dev only; production staging is an owner action. Secrets stay in the existing secure environment and never appear in artifact metadata or command output.

37. **Promote website latest before the canonical appcast** (amends 15 and 36, mac-cleaner #518, 2026-10-30). `scripts/promote-release.sh <dev|prod> ARTIFACT_DIRECTORY HTTPS_FEED_URL` explicitly promotes an already signed and staged artifact set. It verifies the approved EdDSA identity, exact bytes in both download destinations, reviewed notes and generated appcast metadata before advancing the existing website latest record. Stable marketing versions and app builds increase; published identities are immutable. The appcast is promoted last, through the website's `/updates/appcast.xml` route, with an ETag and revalidated caching. The production feed is `https://cachedrop.io/updates/appcast.xml`; enclosures use immutable direct public Supabase updates URLs. Identical retries resume safely after partial promotion; older retries and conflicting bytes/metadata cannot replace or regress a release. The private emailed/tokenized gate keeps delivering the same artifact bytes. The final command verifies the served feed and enclosure, and failure reports completed and remaining state. Dev and production projects/feeds remain separate, and acceptance uses an isolated public test deployment. Building, staging and promotion remain separate owner actions; implementation and acceptance never publish production.
